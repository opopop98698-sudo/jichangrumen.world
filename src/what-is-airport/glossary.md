## 一、基础设施与网络硬件类 (术语 1～5)

### 1. 节点 (Node / Server)
* **工程定义**：部署在全球各地机房的物理或虚拟代理服务器，负责代为接收、转发并回传用户网络请求的中继跳板。
* **通俗比喻**：**航班的目的地机场**（如香港机场、东京机场）。你的数据飞到这里下飞机，再进入当地互联网。
* **新手避坑**：节点不在于数量多，而在于质量精。5 个优质专线节点远胜 300 个超时卡顿的垃圾节点。

### 2. 入口网关 (Ingress Gateway)
* **工程定义**：机场部署在国内骨干网机房的服务器前哨站，负责接收本地客户端发起的第一手加密连接，并将其送入跨境专线。
* **通俗比喻**：**高铁的高架候车厅进站口**。你在家出门先到进站口，才能登上专用高铁列车。
* **新手避坑**：入口越靠近你所在的省份，连接的本地初始延迟越低。多线 BGP 入口能够智能根据你的运营商自动调度最优进站口。

### 3. 落地机房 (Egress Server)
* **工程定义**：位于境外的出口服务器，拥有真实的当地公网 IP，负责真正向 Google、YouTube 或 OpenAI 发起 HTTP/TCP 握手。
* **通俗比喻**：**海外办事处**。办事处的员工代表你在当地向目标网站索取数据，再通过专线传回给你。
* **新手避坑**：落地机房的 IP 质量决定了你能否顺畅解锁 Netflix 版权剧集或通过 ChatGPT 的人机验证。

### 4. IEPL (International Ethernet Private Line)
* **工程定义**：国际以太网专线。由电信运营商直接在两地机房之间铺设的点对点二层内网物理光纤信道，完全独立于民用公网之外。
* **通俗比喻**：**全封闭式海底高铁专用隧道**。不受地面公网塞车（晚高峰拥堵）影响，时刻准点，丢包率几乎为零。
* **新手避坑**：2026 年新手选购机场的核心硬指标，首选采用 IEPL 专线的品牌（如<strong>[光速云](/reviews/#gsy)</strong>）。

### 5. BGP (Border Gateway Protocol)
* **工程定义**：边界网关协议。用于在大型自治系统（AS）之间交换路由信息的动态路由协议。在机场语境中特指“能够同时接入电信、联通、移动、教育网的多线机房”。
* **通俗比喻**：**具备万能转接头的超级智能交通枢纽**。不管你是移动宽带还是电信宽带，进去都能毫秒级无感匹配最优车道。

## 二、客户端与操作系统接管类 (术语 6～10)

### 6. 系统代理 (System Proxy)
* **工程定义**：通过修改操作系统（Windows/macOS）的网络设置注册表，通知遵循系统代理规范的应用（如 Chrome、Edge 浏览器）将流量转发至本地端口。
* **通俗比喻**：**在公司前台贴告示牌**：“查资料请走 7890 窗口”。讲规矩的员工（浏览器）会听从安排。
* **新手避坑**：命令行终端（CMD / Git）和许多游戏客户端无视系统代理，依旧会因直连而报错。

### 7. TUN 虚拟网卡模式 (TUN Mode)
* **工程定义**：客户端在操作系统内核网络层虚拟出一块网络适配器（如 Wintun），通过接管系统默认网关路由表（0.0.0.0/0），对整机所有网络数据包实施 100% 透明拦截与转发。
* **通俗比喻**：**在网卡门口架设全封闭管道**。整台电脑流出的所有数据包无一例外全部被管道截获，强行代理。
* **新手避坑**：需要管理员权限运行客户端。开启 TUN 模式后，终端、游戏、后台服务无需任何配置即可全量出海。

### 8. 规则分流 (Rule-based Routing)
* **工程定义**：客户端根据预设的域名白名单、IP 段列表与 GeoIP 数据库，智能判断数据包的流向：国内网址直接放行，海外受限网址走专线。
* **通俗比喻**：**智能垃圾分类传送带**。国内包裹直接走本地绿色通道，海外包裹打包送上专线飞机。
* **新手避坑**：日常使用坚决开启规则模式（Rule），兼顾国内微信淘宝的 5ms 极速体验，且不浪费机场流量。

### 9. 全局模式 (Global Mode)
* **工程定义**：客户端无视目标网址归属地，强制将所有出站网络流量无脑全部送往海外代理节点。
* **通俗比喻**：**无论买什么菜都必须去美国超市转一圈**。买瓶水也要跨洋绕道。
* **新手避坑**：日常切忌开启全局模式！会导致微信频繁报异地登录风控，国内视频网站提示地区版权限制，且白白消耗宝贵的专线流量。

### 10. 直连模式 (Direct Mode)
* **工程定义**：客户端完全不进行任何代理转发，所有流量原封不动地通过本地宽带直接访问互联网。
* **通俗比喻**：**彻底关闭代理功能**，等同于没有开启软件。

## 三、网络质量与量化指标类 (术语 11～15)

### 11. 延迟 / 往返时延 (Latency / RTT)
* **工程定义**：一个数据包从本地客户端出发，经由代理链路抵达目标服务器并返回确认响应所需的全部时间，单位为毫秒（ms）。
* **通俗比喻**：**两个人在不同山头喊话的回声间隔**。间隔越短，响应越敏捷。
* **新手避坑**：香港专线延迟通常为 30ms～45ms，日本为 55ms～70ms，美国为 130ms～170ms。延迟超过 300ms 网页会有明显迟滞感。

### 12. 延迟抖动 (Jitter)
* **工程定义**：网络延迟在一段时间内的离散方差变化值。
* **通俗比喻**：**水龙头出水是均匀平稳流淌，还是一阵狂喷一阵断水**。
* **新手避坑**：抖动比平均延迟更致命。抖动大的网络会导致视频频繁缓冲、语音通话卡成机械音。专线的抖动方差通常 $\sigma < 1.5\text{ms}$。

### 13. 丢包率 (Packet Loss Rate)
* **工程定义**：在数据传输过程中，未能成功抵达目的地的网络数据包占全部发送数据包的百分比。
* **通俗比喻**：**发了 100 封信，中途被邮局弄丢了多少封**。
* **新手避坑**：丢包率超过 2% 会导致 TCP 下载速度断崖式暴跌。真正的 IEPL 专线丢包率恒定在 **< 0.5%**。

### 14. 吞吐量 / 带宽 (Throughput / Bandwidth)
* **工程定义**：单位时间内在网络链路上成功传输的有效数据量，通常以 Mbps 或 MB/s 为度量单位。
* **通俗比喻**：**水管的粗细直径**。水管越粗，大文件下载越快。
* **新手避坑**：看 4K 视频仅需稳定 30Mbps 即可秒开，无需过分迷信商家宣传的“极限万兆”营销噱头。

### 15. 节点倍率 (Traffic Multiplier / Rate)
* **工程定义**：机场服务商对不同节点所消耗流量设定的计费乘数。
* **通俗比喻**：**出租车的夜间加价倍率**。
* **新手避坑**：
  * **1.0 倍率**：用 1GB 扣 1GB（标准节点）；
  * **0.1 倍率**：用 10GB 仅扣 1GB（冷门/大流量福利节点）；
  * **3.0 倍率**：用 1GB 扣 3GB（昂贵高成本原生 IP 节点）。使用高倍率节点时注意流量消耗速度！

## 四、密码学与通信协议类 (术语 16～20)

### 16. VLESS 协议
* **工程定义**：轻量级无状态代理协议。废除了多余的二次加密计算，将加密工作交由底层 TLS 栈负责，仅保留极简的身份鉴权。
* **通俗比喻**：**给数据包裹贴上一张轻薄的身份条形码**，不再层层加锁。
* **新手避坑**：2026 年主流专线首推标准协议，手机常驻后台不发烫、不耗电。

### 17. TLS 1.3
* **工程定义**：传输层安全性协议的最新密码学标准，支持 0-RTT（零往返时间）快速握手，具备最高等级的前向保密性。
* **通俗比喻**：**现代互联网的防弹运钞车标准**。全球银行与大厂通信的通用底座。

### 18. Reality 伪装技术
* **工程定义**：基于 VLESS 的先进伪装技术。借用海外知名合法商业大厂（如微软、苹果）的真实合规域名与公钥证书建立握手，消除自建域名的特征。
* **通俗比喻**：**直接穿上微软官方的外交官制服出关**。外部审查探针查验时，看到的完全是微软官方的合法凭据。

### 19. Shadowsocks (SS / SS-2022)
* **工程定义**：经典开源对称加密代理协议。以白色纸飞机为图标，开创了现代科学上网技术的先河。
* **通俗比喻**：**特工之间的极简密电密码本**。
* **新手避坑**：兼容性全网第一，几乎所有老旧智能路由器、电视盒子都能完美解析。

### 20. Hysteria 2
* **工程定义**：基于定制 UDP (QUIC) 开发的双向暴躁发包协议，内置单边加速拥塞控制算法。
* **通俗比喻**：**不管路上有没有坑，油门踩到底疯狂狂飙的高速赛车**。
* **新手避坑**：在恶劣丢包网络中提速极猛，但在晚高峰极易被国内部分省份运营商实施全端口 UDP 限速阻断。

## 五、域名、IP 与反风控类 (术语 21～25)

### 21. DNS 污染 / 劫持 (DNS Poisoning)
* **工程定义**：防火墙在网络层伪造并抢先返回错误的 IP 解析结果，导致用户电脑连接到不存在的空地址。
* **通俗比喻**：**问路时被坏人故意指引到悬崖峭壁**。
* **新手避坑**：现代客户端通过配置远端 DoH（DNS over HTTPS）或 Fake-IP 技术可以彻底免疫 DNS 污染。

### 22. DNS 泄漏 (DNS Leak)
* **工程定义**：用户虽然开启了代理，但电脑查询目标域名的 DNS 请求依然通过本地运营商未加密发出，导致运营商日志能清楚记录你正在访问哪些外网域名。
* **通俗比喻**：**戴着面具出门，但逢人就大声报出自己的身份证号**。
* **新手避坑**：在客户端中务必开启“防止 DNS 泄漏”或使用纯净的海外 DNS 解析。

### 23. 原生 IP (Native / Residential IP)
* **工程定义**：IP 地址在国际数据库中登记的归属国与其实际物理机房所在国 100% 一致，且类型标记为当地运营商（ISP）的宽带 IP。
* **通俗比喻**：**持有一张地地道道的当地真实居民身份证**。
* **新手避坑**：解锁 Netflix 全部独家版权大片、登录 ChatGPT 零风控阻断的必备神器。

### 24. 广播机房 IP (Broadcast / Anycast IP)
* **工程定义**：物理服务器部署在美国或欧洲，但通过 BGP 宣告将 IP 地址在软件层面“伪装”映射为香港或日本。
* **通俗比喻**：**人明明在纽约，却打着伪造的香港工牌**。
* **新手避坑**：极易被流媒体和 AI 服务的反欺诈数据库识破并直接拦截。

### 25. 纯净度 / 风险分 (Fraud Score)
* **工程定义**：国际网络安全数据库（如 IPinfo、Scamalytics）根据某个 IP 过去是否发起过爬虫、撞库或垃圾邮件，评估出的风险信用分值（0～100 分）。
* **通俗比喻**：**个人的征信黑白名单报告**。分值越低越纯净，分值越高越容易被各种平台封号。

## 六、订阅、配置与排错类 (术语 26～30)

### 26. 订阅链接 (Subscription URL)
* **工程定义**：机场后台颁发的一串加密 API 接口网址，客户端通过该链接向服务器动态拉取几十个节点的完整配置。
* **通俗比喻**：**包含全部航线信息的电子登机牌**。
* **新手避坑**：属于最高核心私钥凭证，泄露会被他人盗刷流量。严禁未打码发布至公开群聊。

### 27. 订阅转换 (Subconverter)
* **工程定义**：将不同协议格式的节点链接（如将 v2ray 节点转换为 Clash 支持的 YAML 格式）进行语法转译的中间件工具。
* **通俗比喻**：**多国语言同声传译翻译官**。
* **新手避坑**：切勿使用网上来历不明的第三方公开订阅转换网站！不良站长会在后台嗅探并窃取你的订阅 Token。

### 28. Token / UUID
* **工程定义**：长达 32 位的全局唯一标识符（UUID），充当你在机场服务器端的身份认证通行密钥。
* **通俗比喻**：**你的专属指纹识别钥匙**。节点服务器通过这串密钥核实你的流量配额并允许通行。

### 29. 故障转移 (Fallback / Failover)
* **工程定义**：客户端自动化健康检查机制。当第一顺位的主力专线节点发生超时断连时，软件在毫秒内自动将出站流量切换至第二顺位的备用节点。
* **通俗比喻**：**汽车的双回路刹车与备用轮胎**。主胎爆裂瞬间备胎自动顶上，车身毫无颠簸。

### 30. 重置密钥 (Reset Token)
* **工程定义**：在机场用户后台点击重置功能，强制废除旧的订阅密钥，生成全新的加密 Token。
* **通俗比喻**：**发现家门钥匙丢失后，立即给大门换一把新锁**。旧钥匙立刻永久失效，保障安全。

## 七、真实小白术语混淆翻车实录 (1:1 案例库)

### 案例 1：看错“节点倍率”，用 3.0 倍率看 4K 一天烧掉 180G 流量
* **学员档案**：数码爱好者小李，刚购买了某机场的 200GB 月付套餐。
* **踩坑过程**：小李在客户端里选了一个标有“冷门游戏专线 [3.0x]”的节点，在周末挂着看了整整一天 YouTube 4K 电影。周一早晨起床，小李惊恐地发现客户端显示“剩余流量 0GB，服务已被暂停”。小李气愤地找客服理论“我明明只看了 60GB 视频，你们偷我流量”。
* **真相大白**：客服调出日志解释：该节点属于昂贵的游戏专线，标注了 **3.0x 倍率**（消耗 1G 实际扣除 3G）。小李实际消耗的 60GB 流量按 3 倍扣费，正好扣光了 180GB。
* **深层教训**：**连接节点前，务必看清节点名称后面的倍率标注！日常看视频首选 1.0x 或 0.5x 标准节点**。

### 案例 2：误以为“开启代理就绝对安全”，未防范 DNS 泄漏被公司排查
* **学员档案**：某软件公司外包人员小张，在公司办公电脑上挂着代理查阅海外私人招聘信息。
* **翻车教训**：小张以为只要开启了代理，公司网管就什么都看不到。然而小张的客户端未开启“防止 DNS 泄漏”，电脑向公司局域网 DNS 服务器发送了大量境外招聘网站域名的未加密查询请求。次日公司 IT 审计部门直接出具日志通报，对小张进行了严肃约谈。
* **实战结论**：**网络安全必须理解底层原理，防止 DNS 泄漏是保障终极隐私的必修课**。
